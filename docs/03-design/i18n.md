# Idiomas (i18n)

**Regla:** todo texto que ve o escucha el usuario vive en un JSON por idioma. Ningún componente escribe texto fijo: lo pide con `t('clave')`. Hoy hay **español** (`es`, por defecto y referencia) e **inglés** (`en`).

## Dónde está

```text
apps/web/src/shared/i18n/
├─ locales/
│  ├─ es.json            todos los textos en español (referencia: define las claves)
│  └─ en.json            mismas claves en inglés
├─ i18n.js               catálogo de idiomas, translate(), detección y guardado del idioma
├─ I18nContext.js        useI18n()
├─ I18nProvider.jsx      envuelve la app (main.jsx); actualiza <html lang>, <title> y meta description
├─ LanguageSwitcher.jsx  selector ES / EN de la cabecera
└─ index.js              API pública: I18nProvider, LanguageSwitcher, useI18n, LOCALES, DEFAULT_LOCALE
```

## Usarlo en un componente

```jsx
import { useI18n } from '@/shared/i18n';

export function PoiCard({ poi }) {
  const { t } = useI18n();
  return (
    <article aria-label={t('discovery.poiCardLabel', { name: poi.name })}>
      <h3>{poi.name}</h3>                         {/* dato de la API: no se traduce */}
      <p>{t(`discovery.categories.${poi.category}`)}</p>
    </article>
  );
}
```

- `t('grupo.clave')` devuelve el texto del idioma activo. `t('x', { city: 'Cancún' })` sustituye `{city}`.
- Cambiar de idioma re-renderiza todo al instante, sin recargar. El idioma se recuerda en el navegador (`localStorage`, clave `kindhop.locale`); la primera vez se usa el del navegador si existe, si no español.
- Fuera de componentes (p. ej. un `*.api.js`) **no** se traduce: se devuelven códigos (`code`, `category`, `status`) y el componente los convierte con `t()`.

## Organización del JSON

Una sección por feature o zona de la app, con el mismo nombre que su carpeta: `app`, `common`, `language`, `errors`, `cities`, `map`, `dataStatus`… Una feature nueva (`transit`, `discovery`, `events`, `reports`, `budget`) añade su propia sección en **los dos** JSON. Claves en camelCase; los valores de enums del contrato se usan tal cual (`moduleStatus.PLANNED`, `errors.CITY_NOT_FOUND`).

## Qué se traduce y qué no

| Se traduce (va al JSON) | No se traduce |
|---|---|
| Títulos, botones, etiquetas, estados vacíos/carga/error, `aria-label`, `title`, `placeholder`, `alt`, `<title>` y meta description | Datos que llegan de la API o de fuentes (nombres de ciudades, lugares, rutas): se muestran como vienen |
| Mensajes de error: por `code` en `errors.*` | `message` de la API (solo para depurar; la web no lo muestra) |
| Etiquetas de MapLibre (lienzo, zoom, atribución): `map.*`, aplicadas en `CityMap.jsx` | Textos del propio mapa base (calles, etiquetas de OSM) |

## Recetas

**Texto nuevo:** añade la clave en `es.json` y `en.json` → úsala con `t()`. `npm run check` falla si falta en algún idioma.

**Error nuevo de la API:** al crear `throw new AppError(…, 'NUEVO_CODIGO', …)`, añade `errors.NUEVO_CODIGO` en ambos JSON. `ErrorState` lo mostrará solo; si falta, enseña `errors.UNKNOWN`.

**Idioma nuevo (p. ej. francés):** copia `es.json` a `fr.json` y traduce los valores (no las claves); en `i18n.js` añade `import fr from './locales/fr.json'` y `fr` a `MESSAGES`; añade `language.names.fr` y `language.short.fr` en **todos** los JSON. El selector lo muestra solo.

**Cambiar el idioma por defecto:** `DEFAULT_LOCALE` en `i18n.js`. La referencia de claves del verificador es `es.json` (`REFERENCE` en `scripts/check-i18n.mjs`).

## Cómo se hace cumplir

- **ESLint** (`apps/web/eslint.config.js`): error si un `.jsx` tiene texto visible fijo o un `aria-label`/`title`/`placeholder`/`alt` literal.
- **`scripts/check-i18n.mjs`** (dentro de `npm run check`): todos los idiomas con las mismas claves que `es.json`, ningún texto vacío, mismas `{variables}` y toda clave literal de `t('…')` existente.
- En desarrollo, una clave inexistente se ve en pantalla como la propia clave y avisa en consola con `[i18n]`.

**Límites conocidos:** sin plurales ni formato de números/fechas por idioma todavía. Cuando haga falta: `Intl.PluralRules`, `Intl.NumberFormat(locale)` y `Intl.DateTimeFormat(locale)` con el `locale` de `useI18n()`, sin librería nueva.
